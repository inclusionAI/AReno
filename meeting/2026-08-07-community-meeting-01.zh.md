# AReno 社区会议 #1

日期：2026-08-07
时间：14:00-15:00 中国时间（UTC+8）
参会人数：18 人
形式：线上社区会议

## 会议概要

AReno 第一次社区会议顺利举行，共有 18 位同学参与。本次会议主要围绕近期版本更新、多模态能力建设、安装体验优化、贡献者支持和社区协作方式展开。

这也是 AReno 社区第一次固定节奏的社区同步。后续会议纪要和讨论议题会同步到 GitHub，方便社区成员回顾历史讨论、提前提交议题，并通过 issue 跟进后续事项。

## 会议议题

### 1. 社区会议机制

- 社区会议将作为项目进展同步、贡献者交流、问题答疑和 issue 跟进的固定空间。
- 后续会议前，会提前通过 GitHub issue 收集讨论议题。
- 鼓励大家在社群、GitHub issue 或会议中直接提出问题和想法。

### 2. AReno 0.0.7 版本预告

会议同步了即将发布的 `0.0.7` 版本，主要包含三个方向：

- 支持 rollout 和 training 使用不同拓扑，以及 full exchange 能力。
- 初步支持多模态能力，包括 Qwen3.5 和 Qwen3.5-MoE 的图片输入。
- Dashboard 重构，重点优化交互体验和可观测性能力。

除以上主要更新外，该版本也会包含一些 bug fix。

### 3. 多模态能力建设

多模态被认为是 AReno 接下来非常重要的方向之一。

讨论要点：

- 短期优先做好多模态理解能力，重点关注图片、视频、语音输入。
- omni model，即 any-to-any 输入输出能力，短期优先级相对较低。
- Gemma 可作为早期验证模型之一，用来探索图片、视频、语音输入支持，因为它在现有可适配模型中多模态覆盖较完整。
- 图片、语音、视频生成比输入理解更复杂，需要在输入侧能力稳定后再谨慎拆分 scope。

### 4. 安装体验优化

社区同学反馈了安装过程中的问题，尤其是 WSL2、Docker、FlashAttention 和依赖构建耗时等场景。

讨论要点：

- 当前已有 Docker 镜像，但端到端的首次运行体验仍有优化空间。
- FlashAttention 源码编译耗时较长，可以探索针对常见环境提供 prebuilt wheel。
- AI 辅助安装可能成为更友好的新用户路径，但需要更清晰的命令、skill 或安装指引支持。
- 安装文档应尽量保留图片、视频等更丰富的信息，避免纯文本文档丢失关键上下文。

### 5. 训练、Checkpoint 和 GPU 资源

会议中有同学提到训练完成后如何继续使用模型，以及如何处理训练过程中的资源问题。

会议记录：

- 训练产出的 checkpoint 可以下载到本地，并通过兼容的 serving 方式继续使用。
- 遇到显存不足或训练不稳定时，可以降低 rollout 侧显存占用、减小 mini-batch size，或调整 tensor parallel 相关参数。
- 不建议把显存占用压到极限，接近上限的训练更容易因为波动而失败。
- Google Colab 和 Google Cloud 试用额度被提到作为学生可尝试的 GPU 资源方案。

### 6. 贡献者支持和社区运营

- 社区会继续鼓励同学和贡献者尽早提出问题，包括看起来很基础的问题。
- 对优秀贡献者，社区会考虑发放周边，例如包、防晒衣、贴纸等。
- 对愿意撰写 AReno 相关文章或实验报告的同学，社区可以协助润色、发布和传播。
- 近期积极提交 PR、优化文档或持续参与社区建设的贡献者，会被纳入社区激励和认可范围。
