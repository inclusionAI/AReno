# AReno Agent 轨迹详情页 需求文档

> 作者：程言 (chengyan.ts)
> 日期：2026-07-28
> 关联仓库：inclusionAI/AReno
> 原始需求来源：`todo/list`

---

## 1. 背景与动机

AReno 用户需要在 Dashboard 中新增一个 **Agent 轨迹（trajectory）详情页**，作为一项聚焦的、可独立审查的能力。

当前工作流要么缺少该行为，要么依赖用户自行编写一次性代码来实现，导致训练完成后的 run 难以操作、对比和复现。

本需求旨在提供一个统一、一致的契约，使模型消息、工具调用、工具结果、最终答案、token 计数、训练掩码状态和终止原因能够按时间顺序在一个页面中集中展示。

---

## 2. 功能说明

### 2.1 核心功能

页面需按时间先后顺序渲染以下内容：

| 序号 | 内容项 | 说明 |
|------|--------|------|
| 1 | 模型消息 (Model Messages) | 模型在轨迹中产生的所有消息 |
| 2 | 工具调用 (Tool Calls) | 模型发起的工具调用记录 |
| 3 | 工具结果 (Tool Results) | 工具执行返回的结果 |
| 4 | 最终答案 (Final Answer) | 轨迹结束时的最终输出 |
| 5 | token 计数 (Token Counts) | 输入/输出 token 统计 |
| 6 | 训练掩码状态 (Training-mask Status) | 标注哪些片段参与训练 |
| 7 | 终止原因 (End Reason) | 轨迹结束的具体原因 |

### 2.2 展示规则

- **折叠长工具输出**：当工具输出过长时自动折叠，避免页面无限增长。
- **永不执行展示的调用**：页面仅做只读展示，不允许触发任何工具执行。
- **原始 JSON 视图**：提供轨迹原始数据的 JSON 查看模式。

---

## 3. 实现约束

### 3.1 技术约束

1. **复用现有契约**：实现必须使用 AReno 现有的公共契约和本地 artifact 格式，不得引入并行子系统。
2. **安全默认值**：任何新增公共选项必须有保留当前行为的安全默认值。
3. **明确校验错误**：输入校验失败时需给出清晰的错误信息。
4. **双模输出**：通过 CLI 暴露该功能时，需同时提供人类可读输出和结构化输出。

### 3.2 数据来源

- 仅读取**现有本地轨迹 artifact**，不依赖外部数据库。
- 不引入外部数据库、托管控制面或强制重量级依赖。

---

## 4. 用户流程

```
用户显式启用或调用功能
        │
        ▼
AReno 在昂贵的模型/worker 初始化前校验输入
        │
        ├── 校验失败 ──► 明确指出受影响的阶段和输入（不暴露完整训练样本，不隐藏原始错误）
        │
        ▼
功能通过现有日志 / 指标 / artifact / CLI 输出 / Dashboard 产生可观察结果
        │
        ├── 失败 ──► 识别受影响的阶段和输入
        │
        ▼
成功输出轨迹详情
```

### 4.1 失败处理原则

- 识别出受影响的阶段和输入。
- 不暴露完整训练样本。
- 不隐藏原始错误信息。

## 5. 实现区域

优先从以下位置入手，保持改动范围聚焦：

| 区域 | 路径 | 说明 |
|------|------|------|
| 前端 | `dashboard/src/main.jsx` | Dashboard 前端单文件 React 应用，通过 `useState` 管理页面切换（无 React Router）。当前页面定义在 `pages` 数组中（jobs/runtime/launcher/agent），需新增轨迹详情页条目 |
| 后端 HTTP API | `areno/dashboard/server.py` | Dashboard HTTP API 服务器（标准库 `http.server`，1620 行），通过 `do_GET`/`do_POST` 手动分发路由。需新增轨迹详情相关 API 路由 |
| 后端 Agent 上下文 | `areno/dashboard/agent_context.py`、`areno/dashboard/agent_files.py` | Agent 上下文与文件处理辅助逻辑 |
| Dashboard CLI | `areno/cli/dashboard.py`、`areno/cli/dashboard_registry.py` | Dashboard 生命周期命令与任务注册表 |
| 训练状态记录 | `areno/api/dashboard.py` | 训练器向 Dashboard 推送状态的辅助函数（仅 18 行，非 HTTP 入口） |
| 测试 | 前端/API 测试 | 覆盖核心逻辑与集成路径 |

复用现有的数据、指标、生命周期和注册契约，而非引入并行子系统。

---

## 6. 最小示例要求

提供一个**极小的确定性示例或 fixture**，满足以下条件：

- 无需外部数据库即可运行。
- Agent 示例还需避免网络服务和沙箱依赖。
- 必须演示成功路径 + 至少一个无效/边界输入。

---

## 7. 非目标

以下内容不在本次需求范围内：

1. 替换 AReno 的 trainer、rollout engine、本地 dashboard 存储或公共 SDK 架构。
2. 添加外部数据库、托管控制面或强制重量级依赖。
3. 自动修改用户配置、删除 artifact 或终止无关进程。
4. 解决可以作为独立 issue 评审的邻近功能。

---

## 8. 备选方案分析

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 保留在项目特定 loader / reward hook / shell 脚本中 | 改动小 | 无统一契约、无可诊断性、无可复用测试 | 否决 |
| 构建独立服务 | 解耦彻底 | 增加部署和存储复杂度 | 否决 |
| 并入宽泛的 runtime/dashboard 重写 | 统一升级 | 难评审、难测试、难采纳 | 否决 |
| 聚焦新增（本方案） | 易评审、易测试、易采纳 | 需复用现有契约 | **采纳** |

---

## 9. 测试要求

### 9.1 单元测试

- 核心 CPU 测试覆盖核心逻辑
- 测试畸形输入 (malformed input)
- 测试边界值 (boundary values)
- 测试禁用/默认行为 (disabled/default behavior)
- 测试确定性输出 (deterministic output)

### 9.2 集成测试

- 使用极小本地 fixture 进行跨模块集成测试。
- 对于分布式或 GPU-only 行为，使用 fake 隔离编排逻辑，并记录剩余的最低 GPU 验证说明。

### 9.3 断言要求

- 断言发出的指标/artifact 字段和错误信息，而不仅是退出状态。
- 验证功能未启用时现有行为不变。
